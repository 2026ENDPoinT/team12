# 결정 기록

길찾기 개선 작업([routing-spec.md](routing-spec.md))에서 정한 사항을 기록합니다. 최신 결정이 위에 옵니다.

## 2026-11-14 · 지도 보기 경로·출발·도착 표시를 미리 걷기와 같은 모양으로

- **요청**: 지도 보기(위에서 보는 실내 지도)의 경로와 도착 깃발을 미리 걷기와 똑같은 디자인으로 바꾼다.
- **결정**:
  - 모양: 미리 걷기와 같은 얇은 보라 선 + 은은한 반투명 테두리 + 작은 흰색 '>', 바닥 고리 + 가는 기둥 위 구슬.
  - 크기: 지도는 수십 m 위에서 보므로 선 36cm, 테두리 1.3m, 화살표 3.2m 간격으로 키웠다. 출발·도착 표시는 미리 걷기 표시의 4배다.
  - 가림: 지도 보기에서는 선·테두리·화살표·출발/도착 표시가 벽·보에 가려지지 않는다. 미리 걷기는 그대로 보이는 경로만 그린다.
  - 정리: 예전 0.9m 반투명 띠, 삼각 화살표, 공·원뿔 핀은 지웠다.

## 2026-11-14 · 팀이 조사한 계단은 건물을 지나가도 됨

- **결정**: 건물을 가로지를 수 있는 간선은 건물 관통(`building_passage`)과 팀이 조사해 그린 계단(`source_kind: "team_input"`, `feature_type: "stairs"`)이다. `tests/routing.test.mjs`의 건물 관통 검사는 이 둘을 빼고 본다. 자동 생성 길과 팀이 그린 인도는 계속 검사한다.
- **이유**: 100주년기념관에는 건물 아래를 지나가는 바깥 계단이 있다(`path-3`). 건물 윤곽선 데이터로는 건물 안으로 보이지만 현장에서 확인한 실제 통로다. 합칠 때 나오는 "건물을 지나갑니다" 경고는 그대로 둬서 실수로 그린 선은 편집기에서 알아볼 수 있게 한다.
- **남은 문제**: 같은 두 점 사이에 자동 생성 평지 길과 팀 계단이 겹치면(무궁관 출입구 1 앞, 프론티어관 출입구 1 앞), 계단 없는 모드가 평지 길로 지나간다. 팀 계단이 맞으므로 겹친 자동 길을 빼는 코드 수정이 필요하다. 그 전까지 `step-free mode excludes registered stairs` 테스트가 실패한다.

## 2026-11-13 · 호실 이름을 층별 안내판 기준으로

- **배경**: 3층 이름이 옛 도면 그대로였다(예: 308호 '데이터베이스 실습 준비실'인데 안내판은 '이동지능연구실2'). 교수연구실은 교수 이름이 없었고, 1층·지하 1층은 이름이 비어 있었다.
- **결정**: 미래관 1층 층별 안내판 사진(2026-11-13)을 기준으로 지하 1층~3층 75곳을 등록했다(`data/mirae/room-names.json`).
  - `mirae.json`의 `names`에 반영했다. 원본에서 다시 뽑아도 이 파일이 우선하도록 `scripts/extract-mirae.py`를 고쳤다.
  - 기존 데이터의 연구실 담당 교수(괄호)는 같은 연구실로 보이는 곳에 남겼다: 207 김준수(기존 208), 213 권도훈, 214 이의진, 215 한창희, 216 정재영.
  - 지하 1층 호실(B104 등)은 이름이 적용되지 않던 문제를 고쳤다.
- **남은 것**:
  - 안내판에 없는 114·115·212·217호와 이름이 빈 306호는 그대로 둔다.
  - 안내판에만 있는 306-1·309-1호는 도면에 없어서 넣지 않았다.
  - 4·5층은 도면이 없어 넣지 않았다.
- 원본 사진은 반영 뒤 지웠다(커밋하지 않음).

## 2026-11-13 · 실내 출발 위치 5곳, 걸어 보기 경로·도착 표시 다듬기, 엘리베이터 문

- **출발 위치**: 팀 조사 출입구(`data/team-survey.json`)를 도면 좌표로 옮겨 다섯 곳으로 늘렸다.
  - 1층 로비 정문, 1층 로비 후문(ent-future-1), 1층 측면 입구 106호 쪽(ent-future-3), 1층 서쪽 입구 103호 쪽(ent-future-4), 지하 1층 출입구(ent-future-7).
  - 조사 점은 건물 바깥이라, 가장 가까운 건물 안 걸을 수 있는 곳(방 안 제외)으로 옮겼다. 원래 좌표는 `entrances.json` note에 남겼다.
  - 출입구마다 캠퍼스 노드를 여러 개(`campusNodes`) 둘 수 있게 했다. 캠퍼스 경로가 그 출입구로 오면 거기서 실내 안내를 시작한다.
- **걸어 보기 경로**: 지도용 0.9m 띠가 눈높이에서는 복도를 덮을 만큼 두꺼워 보여서, 걸어 보기 전용 모양을 따로 그린다. 지도 보기 모양은 그대로다.
  - 얇은 보라 선(14cm), 은은한 반투명 테두리(50cm), 1.4m마다 작은 흰색 '>'.
- **도착 표시(걸어 보기)**: 높이 3m 공·원뿔 대신 바닥 고리(보라·흰) + 가는 기둥 위 작은 구슬(1.15m). 출발은 바닥의 작은 고리.
- **엘리베이터 문**: 나무 질감 대신 샴페인 골드 헤어라인 금속에, 가운데 세로 틈(양쪽으로 열리는 문)과 양옆 틈.
- **미리 걷기 시작·끝**:
  - 안내 목록에서 누른 단계가 있으면 그 단계 2m 앞에서 시작한다. 다시 재생해도 거기서 시작한다. 지난 엘리베이터 장면은 건너뛴다.
  - 도착 표시 위에 올라서지 않도록 3.2m 앞에서 멈추고, 마지막 3m 동안 표시 쪽으로 돌아선다.

## 2026-11-13 · 걸어 보기에서는 지금 시점에서 보이는 경로만

- **문제**: 경로 미리보기(1인칭)에서 경로 띠의 반투명 테두리·화살표·출발/도착 표시가 벽을 통과해 보였다. 3층처럼 복도가 많은 곳에서는 벽 너머 경로가 겹쳐 복잡했다.
  - 원인: 지도 보기에서 벽 아래 경로도 보이도록 이 표시들을 '가려지지 않음'(depthTest: false)으로 그렸다.
- **결정**: 걸어 보기일 때만 경로 표시를 벽·바닥에 가려지게 하고, 지도 보기는 그대로 둔다.
  - 글자 표시(층 이동, 안내 번호)는 HTML이라 깊이로 가려지지 않는다. 그래서 같은 층이고 걷기 격자로 벽에 막히지 않을 때만 보인다(25m 안).

## 2026-11-13 · 지도 화면 데스크톱 UI를 Figma v2 디자인으로 바꿈

- **요청**: Figma "길찾기 · 유저 플로우 v2" 디자인을 데스크톱(761px 이상) 지도 화면에 적용한다. 기존 화면 디자인을 바꾸는 것이라 사용자 요청과 확인을 받고 진행했다. 모바일은 다음 작업으로 미룬다.

- **지도**: 화면 전체를 지도로 쓰고, 패널·카드는 지도 위에 뜨는 반투명 유리(프로스트) 카드로 바꾼다.

  - "실내 탐색"은 main의 3D 진입 전환(`enterIndoor`, PR 18)으로 건물 안까지 날아간 뒤 실내 지도를 연다. 처음에 만든 0.7초 로딩 화면은 main 병합 때 이 전환으로 바꿨다. 실내 지도가 있는 건물(`INDOOR_MAPS`, 지금은 미래관)만 버튼이 켜진다.

  - 경로 카드: 제목은 경로 방식(최단 경로/계단 피하기), 시간·거리, 안내 단계마다 다음 지점까지 거리, "안내 시작".
  - "안내 시작"은 단계별 안내 기능이 없어 출발지로 지도를 옮기고 안내 문구만 띄운다.
- **지도 컨트롤**: Figma처럼 오른쪽 아래에 2D/3D · 확대·축소 · 내 위치 · 시점 초기화를 세로로 둔다. 결과 카드가 있으면 카드 왼쪽으로 옮긴다.
- **지도 데이터 출처**: 패널을 닫아도 보이도록 지도 아래 가운데에 짧은 출처 문구를 항상 표시한다.
- **바꾸지 않은 것**: 경로 계산, 길 막힘 제보·관리자 검토 동작, GPS, 편집 모드, 모바일 화면.

## 2026-11-13 · 3D 실사 질감은 되돌리고, 그리기 성능만 최적화

- **시도**: 원본 영상에서 바닥·벽·문 질감을 펴서 입히고 구석 그림자(AO) 후처리를 넣었다.
- **결과**: 사용자 확인 결과 너무 칙칙하고 무거워서 되돌렸다. 기존(코드로 그린 질감) 모습을 유지한다.
  - 뽑아 둔 질감과 추출 스크립트는 커밋하지 않았다.
- **최적화** (모습은 그대로, `src/indoor/view.js`):
  - 걸어 보기 화면은 위치·방향이 바뀔 때만 다시 그린다. 예전에는 가만히 있어도 매 프레임 그렸다.
  - 화면을 움직이는 동안만 해상도를 낮추고(배율 최대 1.25), 멈추고 0.25초 뒤 원래 해상도(최대 2)로 다시 그린다.
  - 배율 1.5 이상 화면에서는 안티에일리어싱을 끈다.
  - 호실 이름표 갱신은 0.12초에 한 번으로 줄였다. 질감 필터링(이방성)은 8에서 4로 낮췄다.
- **참고**: 원본 영상의 카메라 자세로 바닥을 펴 보니 실제 바닥은 40cm 테라조 타일과 40×160cm 짙은 석재 띠였다.

## 2026-11-13 · AR을 업계 표준 구조로: VIO(WebXR·ARCore) + 사진 후보 RANSAC 정렬

- **배경**: 실내 AR 상용 서비스(구글 라이브뷰, Immersal, Niantic 등)는 모두 두 단계로 나눈다.
  1. 휴대폰 자체의 VIO(카메라 + 관성 센서, ARCore/ARKit)로 1초에 60번 6축 움직임을 cm 단위로 추적한다.
  2. 몇 초마다 이미지로 절대 위치(VPS)를 맞춘다.
  - 지금까지는 방향 센서(회전만 앎)와 걸음 수로 움직임을 이어 가서 방향이 흔들리고 경로가 떨렸다.
  - 실내 GPS는 오차가 10~50m라 평면 위치를 정하는 데 쓰지 않는다(입구 인계·이상 위치 거르기 같은 보조로만 검토).
- **결정** (`src/indoor/ar/xr.js`, `xr-math.mjs`):
  - **세션:** 안드로이드 크롬(WebXR immersive-ar)에서는 local-floor + camera-access + dom-overlay로 AR 세션을 연다.
  - **VIO와 경로:** 경로는 VIO 세계에 고정해 그린다. 실제 바닥에 붙고, 위치·방향·속도는 매 프레임 VIO가 낸다.

- **원인 2**: 안내 생성이 "짧은 구간의 꺾임은 합친다" 규칙으로 0.45m 조각 위의 실제 90° 회전을 버렸다. 계단·엘리베이터에서 나올 때 바라보는 방향 기준도 없었다.
- **고친 것**
  - 경로 탐색에 벽 옆 칸 비용(1.7배·1.2배)을 더해 복도 가운데로 걷게 했다.
  - 다듬기는 진행 방향 좌우 0.25m 여유를 검사하고, RDP 단순화(0.35m)로 남은 지그재그를 정리한다.
  - 회전 판단은 꺾인 점의 앞뒤 3m 방향으로 하고, 3m 안의 연속 꺾임은 합쳐 전체 각도로 판단한다(35° 미만은 직진).
  - 계단은 경사로의 첫·마지막 구간, 엘리베이터는 문 ↔ 칸 중심 방향으로 진입·진출 방향을 정해 "왼쪽에 있는 계단으로", "계단에서 나와 오른쪽으로"를 안내한다.
  - 회전 지점 3.5m 안의 호실을 기준으로 붙인다("222호 앞에서").
  - 단계마다 경로상 거리(s)를 저장해 지도 번호 표시, 미리 걷기, AR 진행률이 같은 기준을 쓴다.
  - 테스트: 안내한 좌·우가 경로 기하와 맞는지 6개 경로에서 확인한다.
- **엘리베이터**
  - 미리 걷기는 문 닫힘 → 층 표시 증가 → 도착음 → 문 열림 장면을 재생한다.
  - AR은 문 앞에 오면 "3F 버튼을 누르세요" 탑승 화면을 띄우고, 도착 층에서 위치가 다시 잡히면 문이 열리며 안내를 이어 간다. 위치를 못 잡을 때는 "내렸어요" 버튼으로 넘어간다.
  - 지도에서 층을 바꾸면 카메라가 층 높이만큼 오르내리고 큰 층 표시가 나온다.
- **도착 지점**
  - 경로가 방 안이나 문틀 가운데가 아니라, 문이 놓인 벽에서 복도 쪽으로 0.7m 떨어진 문 앞에서 끝난다(공간이 좁으면 0.4~1.1m).
  - 도착 안내의 좌·우와 AR 도착 문구("문은 왼쪽")는 문 위치를 기준으로 하고, 미리 걷기는 마지막 1.2m에서 문을 바라보도록 돌아선다.
  - 테스트: 모든 목적지(100곳)의 도착점이 방 밖, 문에서 0.3~1.3m 안에 있는지 확인한다.
- **계단 없이 모드**
  - 엘리베이터가 닿지 않는 층(현재 도면상 B1)으로 가면 경로가 아예 나오지 않던 것을, 계단 한 개 층마다 큰 비용(2000m 환산)을 더해 계단을 최소로 쓰는 경로로 안내하게 바꿨다. 예: 313호 → B104는 엘리베이터 3F→1F, 계단 1F→B1.
  - 이때 경로 요약에 "엘리베이터가 닿지 않는 층이 있어 1F→B1 구간만 계단을 이용해요"를 표시한다.
  - 빠른 길은 걷는 거리·엘리베이터 대기를 합친 최단 경로를 쓰되, 계단으로 3개 층 이상 오르내리게 되면 엘리베이터 경로(계단 최소)로 바꾼다(사용자 결정). 이때 "3개 층 이상이라 엘리베이터로 안내해요"를 표시한다. 1~2개 층은 계단 그대로.
- **사용성·안정성**
  - 안내 목록과 지도 번호를 연결해, 목록을 누르면 그 지점으로 날아간다.
  - 미리 걷기에 재생·정지, 이전·다음 단계, 1·2·4배속을 넣었다.
  - 음성 안내 켜기·끄기(설정 기억), 최근 검색, 출발·도착 바꾸기, 경로 공유 링크(`?from=&to=&mode=`)를 추가했다.
  - AR에 화면 꺼짐 방지(Wake Lock)와 다른 앱 전환 뒤 위치 다시 찾기를 넣었다. 신뢰도가 낮을 때는 바닥 경로를 숨기고, 확실히 벗어났을 때만 재탐색한다.
  - 카메라를 켜지 못했을 때 오류 창 버튼이 동작하지 않던 버그를 고쳤다.

## 2026-11-12 · 미래관 실내 지도·AR 길안내 통합 (명세 Phase 7)

  - 명세의 "한 번의 `findRoute`로 정문 → 강의실" 통합은 아직 하지 않았다. 실외 경로는 로비 출입구에서 끝나고, 실내 경로가 거기서 이어진다.

## 2026-11-12 · 신고 단계·사유·사진 필수, 건물 공사 표시, 건물 번호

- **신고 단계**: 접수(지도에 안 보임) → 같은 구간에 신고 3건 이상이면 주의(노란색) + 관리자 검토 알림 → 관리자가 확정하면 경고(빨간색)이고 그때만 우회 경로. 노란색은 경로를 바꾸지 않는다. 이전에는 1건부터 노란색이었다.
- **3건 세는 법**: 같은 기기(`reporter_device_id`)가 같은 구간을 여러 번 신고해도 1건으로 센다. 한 사람이 혼자 노란색을 만들지 못하게 하려는 것이다.
- **사유 3가지**: 공사 중(`construction`), 장애물·통제(`blocked`), 기타 직접 입력(`other` + `reason_note`, 100자까지, 비우면 신고 불가).
- **사진 필수**: 사진이 있어야 신고 버튼이 켜진다. 업로드가 실패하면 신고도 저장하지 않는다(이전에는 사진 없이 저장했다). 카메라는 `<input capture="environment">`로 휴대폰 뒷카메라를 바로 연다. 앱 안 카메라 화면(getUserMedia)은 만들지 않는다. Storage 경로에는 파일 이름 대신 확장자만 쓴다(한글 파일 이름 오류 방지).

- **순서**: 디버그 오버레이 → 합치기(팀 조사 파일 → 그래프) → 자동 검사 → 편집 모드. 명세는 편집 모드가 먼저지만, 합치기가 있어야 조사 데이터가 경로에 반영되므로 앞당긴다. 합치기는 원래 Phase 2·3에 속하는 기능이다.

- **기존 길에 붙이는 방식**: 가장 가까운 간선에 수선을 내린 점에서 간선을 둘로 자르고 연결한다. 연결선이 건물을 지나면 다음 간선을 쓴다. 끝점 1m 안이면 자르지 않고 그 노드를 쓴다. 자른 점 id는 조사 항목 id에서 만들어 매번 같은 결과가 나온다.
- **신고 보존**: 간선이 잘려 간선 id가 바뀌어도, 저장된 클릭 좌표로 가장 가까운 간선을 다시 찾아 신고를 유지한다.

- **검사 기준**: 경로를 틀리게 만드는 경고(연결 안 된 섬, 건물 관통, 중복 노드)는 캠퍼스 전체 0건. 끊긴 길은 데모 경로 주변만 0건이고, 나머지는 표시만 한다.
- **편집기 구조**: 같은 저장소의 `src/editor/`에 두고 별도 파일(`editor.js`)로 빌드한다. 주소에 `?edit=1`이 있을 때만 불러오므로 일반 화면과 다운로드 크기는 바뀌지 않는다.
  - 예외: 그래프 디버그 오버레이(`src/graph-overlay.js`)는 Three.js로 그려야 해서 앱 본체에 넣었다. 수 KB이고 `?edit=1`에서 켤 때만 실행된다. 토글과 범례는 `src/edit-mode.js`에 있다.
