# 실내 지도·AR 데이터 관리

## 원칙

실행에 필요한 데이터와 촬영 원본을 분리합니다. GitHub Pages와 공개 Git 저장소에 올라간 파일은 비밀로 보호할 수 없으므로, 공개 가능한 파생 데이터만 `data/mirae/`에 둡니다.

| 등급             | 예시                                       | 저장 위치                    | Git  | 웹 배포 |
| ---------------- | ------------------------------------------ | ---------------------------- | ---- | ------- |
| 공개 실행 데이터 | GLB, 보행 그래프, 출입구, 카메라 좌표·자세 | `data/mirae/`                | 가능 | 가능    |
| 공개 파생 데이터 | 밝기 특징량 `ar-index.bin`                 | `data/mirae/`                | 가능 | 가능    |
| 제한 데이터      | 실내 검증 사진, 원본 촬영 영상             | `private/mirae/`, `room.mp4` | 금지 | 금지    |
| 비밀             | DB 비밀번호, 서비스 키                     | `.env*`, 배포 플랫폼 Secret  | 금지 | 금지    |

`sv.json`에는 사진 자체가 아니라 기준 프레임 ID, 층, 실내 좌표, 카메라 회전이 들어 있습니다. `ar-index.bin`에는 사진마다 46×20칸의 흐린 밝기 특징량만 들어 있어 원본 화면을 직접 표시하는 용도로 사용하지 않습니다.

## 데이터 흐름

1. 검증 사진을 `private/mirae/sv/`에 둡니다.
2. 처음 한 번 `python3 -m pip install -r scripts/requirements-ar.txt`로 생성 도구를 준비합니다.
3. `python scripts/build-ar-index.py`를 실행해 `data/mirae/ar-index.bin`을 갱신합니다.
4. `npm test`로 인덱스와 메타데이터의 개수·형식이 맞는지 확인합니다.
5. `npm run build`가 허용된 파일만 `dist/indoor/assets/`에 복사합니다.
6. AR 실행 시 카메라 프레임을 최대 약 220px 특징량으로 축소하고 Web Worker로 보냅니다. 계산은 사용자 기기 안에서 끝나며 원본 프레임이나 촬영 화면을 서버로 업로드하지 않습니다.

## 갱신 규칙

- 기준 사진을 추가·삭제하면 `sv.json`과 `ar-index.bin`을 반드시 함께 갱신합니다. 런타임 검증이 두 파일의 버전 불일치를 차단합니다.
- `scripts/indoor-assets.mjs`의 `PUBLIC_INDOOR_ASSETS`가 공개 배포 허용 목록입니다. 사진 폴더를 이 목록에 추가하지 않습니다.
- `dist/indoor/assets/`는 빌드 결과이므로 직접 수정하거나 커밋하지 않습니다.
- 원본 사진을 팀과 공유해야 할 때는 공개 Git이나 Git LFS가 아니라 접근 권한·만료·삭제 정책을 설정할 수 있는 비공개 저장소를 사용합니다.
- 현재 Git 이력에는 과거 사진 커밋이 남아 있을 수 있습니다. 팀 전원이 동의한 뒤 별도 작업으로 이력을 정리하고, 기존 복제본도 다시 받도록 안내해야 완전히 제거됩니다.

## 브라우저 보안

- 카메라는 HTTPS/localhost에서 사용자 동의를 받은 뒤에만 엽니다.
- 임의 외부 주소로 카메라 프레임을 전송하던 `?loc=` 기능은 사용하지 않습니다.
- 실내 페이지 CSP의 `connect-src 'self'`가 다른 출처로의 `fetch` 연결을 차단합니다.
- 외부 웹폰트 요청을 없애 실내 페이지가 자체 출처의 코드·데이터만 사용합니다.
- AR 종료 시 카메라 트랙, 센서 이벤트, Worker, WebXR 세션을 모두 정리합니다.
